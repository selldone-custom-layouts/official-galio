# AI Agent Entry Point

Detailed AI instructions and reusable custom Storefront Layout material live
in the dedicated [`.ai-agent/`](.ai-agent/) directory so they stay separate
from application source.

For tasks that customize, redesign, audit, package, or publish this Storefront
as a custom Selldone Layout, read these files completely:

1. [`.ai-agent/AGENTS.md`](.ai-agent/AGENTS.md)
2. [`.ai-agent/SKILL.md`](.ai-agent/SKILL.md)
3. [`.ai-agent/AI_WORKFLOW.md`](.ai-agent/AI_WORKFLOW.md) when GitHub setup,
   dependency synchronization, packaging, authentication, or deployment is in
   scope

The official Vue 3/Vite Storefront is the implementation baseline. This kit
does not authorize a framework replacement or a parallel storefront app; the
visual design may change completely while the platform and commerce contracts
remain intact. Do not change the official repository's Git remote model or run
release commands merely because this shim exists. Apply publication rules in
the owner's controlled clone, fork, or release branch.

## Theme (palette, brand colour, light or dark, the visitor switcher)

When a merchant asks for a theme ("use the yellow theme", "my brand colour is #F5C400", "make it dark"), edit **one file only**: `components/galio/galio-theme.settings.ts`. Nothing else needs to change, and the colours are made readable automatically (buttons, links, chosen states, dark mode). Galio Sundae uses one colour family: every colour comes from the chosen palette's hue (cherry by default), plus white and the family's near-black, so a palette or brand colour re-tints the grounds, bands, plates, rail and footer as well as the buttons.

| Setting | Allowed values |
| --- | --- |
| `palette` | `"cherry"` (the brand; the default), `"pistachio"`, `"blueberry"`, `"cocoa"` |
| `brandColor` | any `"#RRGGBB"`; when set it replaces `palette` |
| `mode` | `"light"` (white pages and the family's light tints; the default) or `"dark"` (the same family's night) |
| `themeSwitcher` | `"showcase"` (the visitor switcher shows only on the showcase shops listed in `showcaseShops` in `components/galio/galio-theme.ts`, Bakio 15740 among them; the default), `"on"` (the merchant's visitors get the Theme row in the footer), `"off"` |
| `textOnBrand` | only with `brandColor`: `"auto"` (a light brand such as yellow keeps its colour, with dark words on it) or `"white"` (white words; a light colour is darkened) |

Worked examples (change only these lines; leave the rest of the file as it is):

- **"Use the yellow theme"**: no tested palette is yellow, so use a brand colour: `brandColor: "#F5C400", textOnBrand: "auto"`.
- **"My brand colour is #F5C400"**: `brandColor: "#F5C400", textOnBrand: "auto"`. Use `textOnBrand: "white"` if they want white words; the colour is then darkened.
- **"Make it dark"**: `mode: "dark"`.
- **"Let visitors switch themes"**: `themeSwitcher: "on"`.
- **"Remove the switcher"**: `themeSwitcher: "off"`. On a merchant's own shop it is already hidden with `"showcase"`.
- **"Go back to the original colours"**: remove `brandColor` and set `palette: "cherry", mode: "light"`.

The switcher itself is the shared package in `components/theme-switcher/` (the same code as every other Layout; see its PORTING.md in the kit). Galio's palettes (the action colours) are in `components/galio/galio-theme.ts`. The family is computed from the palette's colour in OKLCH by `components/galio/galio-family.ts` (`--gl-fam-*` and `--gl-on-ink-*` on `<html>`, light and dark, following every palette, mode and Custom change); `style/galio/one.css` (generated by `scripts/galio-css.cjs` from `galio-design/g/one.css`) carries the Cherry family for the first paint and maps the mockup's tokens in `style/galio/b.css` onto it, and the end of `style/galio.scss` maps the base Layout's `--bk-*` grounds and words onto it. Do not edit any of them for a merchant's theme.

Then release and check:

1. Build and upload: `LAYOUT_ID=<your Layout id> PW=<playwright>/index.js SELLDONE_CLI_SRC=<cli clone> bash scripts/release.sh <new version> desk` (`PW` is the Playwright install the release's production check uses; see "Releases" below). Put the version live.
2. Check the contrast on the live shop. It must print `TOTAL 0`:
   ```sh
   PAGES="home=/,category=/<a category>,product=/product/<id>" node components/theme-switcher/tools/contrast-audit.cjs https://<your shop> ".gl-ftr footer"
   ```
3. If the visitor switcher is on, also run the kit's `ring-sweep.cjs` in light and dark (`STORAGE='{"galio-theme":"{\\"palette\\":\\"cherry\\",\\"mode\\":\\"dark\\"}"}'`). The switcher is the Theme row in the footer.

## Words and languages

Galio's own words go through `t("galio.<area>.<name>", "English")` (`components/kalio/i18n/kalio-i18n.ts`, the shared i18n runtime). The English is `components/kalio/i18n/base/en.ts` (the shared Kalio words), `bakini.en.ts` (only the 159 `bakini.*` words Galio still uses from the Layout it started from: badges, delivery way names, units) and `galio.en.ts` (Galio's own, `galio.*`), generated from the code by the kit's `i18n-extract.cjs`; `index.ts` merges them into `EN`. Arabic is `base/ar.ts` + `bakini.ar.ts` + `galio.ar.ts`, merged by `lang-ar.ts` and listed in `index.ts` (`LOADERS`), fetched only when a visitor picks it. A new word goes into `galio.*`, never into `bakini.*`. The basket is a **bag** everywhere ("Add to bag", "Your bag"), in the Layout's words and in Selldone's own English strings (`components/kalio/kalio-brand.ts`, `bagWords()`). Bakio, the showcase shop, sells in English only; on the dev server `localStorage["galio-dev-languages"] = "ar"` adds Arabic to the shop's languages in that browser (`mixin/StorefrontMixin.ts`, development only, not in the build). To add a language the shop enables: translate `galio.en.ts` to `galio.<code>.ts` and `bakini.en.ts` to `bakini.<code>.ts` (same keys, keep every `{…}`, add the language's plural forms), copy `base/<code>.ts` from the shared set, add `lang-<code>.ts` (three imports, like `lang-ar.ts`) and one `LOADERS` line. A new visible word always gets a `t()` key; a word still in English after a language pick is an unwrapped string. Use logical CSS (`margin-inline`, `inset-inline`, `text-align: start`) so a right-to-left language mirrors.

## Where Galio's parts are

Galio's components are in `components/galio/` (`shell/`, `home/`, `shop/`, `product/`, `compare/`, `buy/`, `account/`, `read/`, and the shared `gl-data.ts`, `galio.ts`, `gl-icons.ts`, `gl-photos.ts`, `Gl*.vue`). Every one wraps its markup in an element with the class `gl`; its tokens are `--gl-*`. The mockup's stylesheets are generated into `style/galio/*.css` by `scripts/galio-css.cjs` and never edited by hand; the Layout's own touches go in `style/galio.scss` and `style/galio-buy.scss`. The parts Selldone and the shared Kalio base still draw read `--bk-*` tokens (the action colours written by Galio's switcher from the palette; the grounds, words and plates mapped onto the family at the end of `style/galio.scss`) and `html.bk-dark`, which follows `html.gl-dark`. `GALIO.md` is the project's notes: how each page was built, the data rules, the checks and the releases.

## Releases

Release with `scripts/release.sh` only (see the wiki page "Build and Upload"). Its step 5b, `scripts/galio-prod-check.mjs`, loads the **built** bundle through the shop's real storefront HTML in headless Chromium before anything is uploaded, and stops the release on any page error. Never skip it: dev checks never see chunking bugs (Galio 1.0.0 was blank live from `ReferenceError: Prism is not defined` after every dev check had passed). Keep `coreChunk` in `vite.config.ts` limited to the Layout's own source. On Bakio, the showcase shop, Galio is Layout 39, pinned on its own domain `galio.selldone.shop` (Selldone domain 1249) only; the shop default is Bakini Noir (Layout 36) and is never changed by a Galio release.
